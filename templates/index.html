08 / About This Simulator

OVERVIEW

WHAT IS CPU SCHEDULING?

A computer usually has more processes ready to run than it has CPU cores. The scheduler is the part of the operating system that decides which ready process gets the CPU, and for how long. The choice strongly affects responsiveness, fairness, and throughput.

This simulator models a single CPU. Each process has an arrival time (when it enters the system), a burst time (how much CPU work it needs), and a priority (used only by Priority scheduling).

HOW THE SIMULATION WORKS

The simulator runs in discrete time units. At every decision point it chooses the next process according to the algorithm, records a segment (process, start time, end time), and moves the clock forward. Every segment is drawn in the Gantt chart, and all metrics are computed from the resulting trace. No randomness is involved, so the same input always gives the same output.

HOW TO USE IT

  1. Choose an algorithm from the dropdown. The mode badge, the description, and the CPU Monitor update automatically. Round Robin also shows a time-quantum field.
  2. Define processes. Edit PID, arrival, burst, and priority. Use + ADD PROCESS to add rows, the × button to remove them, or LOAD SAMPLE to fill in a textbook example.
  3. Run. Press RUN SIMULATION. The Gantt chart animates the schedule, the CPU Monitor clock counts up, the stat cards update, and the results table fills in.
  4. Read the Gantt chart. Each row is one process. Amber markers show arrival times, and hatched blocks are idle CPU time. The bottom lane shows the CPU's full sequence. Hover any block for exact times.
  5. Compare. Press COMPARE ALL ALGORITHMS to run every scheduler on the same workload. The best average waiting time is highlighted.
  6. Replay. Press REPLAY to watch the animation and the clock again.

09 / Scheduling Algorithms Explained

ALGORITHMS

FCFS — FIRST COME, FIRST SERVED

The simplest policy. Processes run in the order they arrive. Once a process starts, it keeps the CPU until it finishes, so this is non-preemptive.

  • Pros: easy to implement, fair in arrival order, no starvation.
  • Cons: suffers from the convoy effect. One long job at the front makes every short job behind it wait.
  • Best for: batch systems where job order matters more than response time.

SJF — SHORTEST JOB FIRST

Among the processes that have arrived, the one with the smallest burst time runs next. This simulator uses the non-preemptive variant.

  • Pros: gives the lowest possible average waiting time for a given set of non-preemptive jobs.
  • Cons: long jobs can starve if short jobs keep arriving. Real systems cannot know burst times in advance, so they estimate them.
  • Best for: workloads with known, widely varying job lengths.

PRIORITY SCHEDULING

Each process has a priority, and the ready process with the lowest number runs first (1 is the highest priority here). Ties are broken by arrival time. This variant is also non-preemptive.

  • Pros: important work (such as interrupt handling or interactive tasks) can be favored.
  • Cons: low-priority processes may starve. The usual fix is aging, where priority gradually increases the longer a process waits.
  • Best for: systems with clearly ranked tasks.

ROUND ROBIN (RR)

Each process gets the CPU for at most one time quantum. If it still needs time, it goes to the back of the ready queue. This is preemptive.

  • Pros: fair, good response time, and well suited to interactive systems.
  • Cons: a very small quantum causes too many context switches, and a very large one behaves like FCFS.
  • Best for: time-sharing systems. Try changing the quantum and watch the switch count move.

10 / Performance Metrics

FORMULAS

COMPLETION TIME (CT)

The time at which a process finishes its last CPU burst.

CT = end time of the process's final segment

TURNAROUND TIME (TAT)

Total time a process spends in the system, from arrival to completion.

TAT = CT − Arrival

WAITING TIME (WT)

Time a process spends in the ready queue, not running. This is the metric scheduling policies usually try to minimize.

WT = TAT − Burst

CPU UTILIZATION

The percentage of time the CPU does useful work rather than sitting idle.

Utilization = Busy time / Total time × 100

THROUGHPUT

How many processes finish per time unit. Higher is better.

Throughput = Processes / Total time

CONTEXT SWITCHES

How many times the CPU changes from one process to a different one. Each switch has an overhead in a real OS, so fewer is cheaper.

Count of consecutive segments with different PIDs

Response time (time to first CPU access) is not reported separately. In this non-preemptive model it equals waiting time, and it differs for Round Robin.

12 / Glossary

REFERENCE
Preemptive
The scheduler can take the CPU away from a running process before it finishes.
Non-preemptive
A process keeps the CPU until it completes or blocks.
Quantum
The maximum CPU slice a process gets per turn in Round Robin.
Starvation
A process waits indefinitely because others are always chosen first.
Convoy effect
Short processes queue behind one long process, inflating average waiting time.
Idle time
Periods when no process is ready, so the CPU has nothing to do.
